# Novel Writing — 文学向小说创作

## 概述

本技能用于创作文学向短篇/中篇小说（数千至十万字）。核心理念：**先立意，再结构，后文字**。小说不是情节的堆砌，而是"某个具体的人在某个具体处境中的具体体验"——始终围绕这一点工作。

## 工作流决策树

接到创作请求后，先判断进入哪个模式：

| 用户情形 | 模式 | 入口 |
|---|---|---|
| 只有一个点子/一句话/模糊主题，想写一篇小说 | A 从零构思 | 见模式 A |
| 已有大纲、人物设定或开头，要求继续写正文 | B 大纲→正文 | 见模式 B |
| 已有写好的文本，要求续写、润色、改写、扩写 | C 续写/润色 | 见模式 C |
| 要求维护设定集、检查前后矛盾、追踪人物状态 | D 设定管理 | 见模式 D |

判断不清时直接询问用户。多模式混合（如"帮我构思并写第一章"）按 A→B 顺序执行。

## 模式 A：从零构思整篇

1. **明确立意与体量**。先与用户确认：核心想表达什么（一句话），目标篇幅（微篇<3k / 短篇3k–2w / 中篇2w–10w），偏好基调。若用户只给了模糊点子，提出 2–3 个不同切入角度供选择，不要直接开写。
2. **建项目骨架**。运行 `scripts/init_novel_project.py <项目目录名> [--path 父目录]`，生成含设定集、大纲、章节目录的标准项目结构。项目默认建在用户工作区下。
3. **填人物档案**。使用 `assets/character-sheet.md` 模板，为每个主要人物建档。人物要有**欲望—障碍—缺陷**三要素，缺陷必须与欲望冲突。
4. **填世界观/背景设定**。短篇只需 `assets/world-bible.md` 中的精简版；中篇用完整版。
5. **定文风表**。使用 `assets/style-sheet.md`，确定叙事视角、时态、语言密度、意象系统。**视角一经确定不得中途切换**（除非有意为之并事先说明）。
6. **写大纲**。使用 `assets/outline-template.md`。短篇按"场景清单"而非章节组织；中篇按三幕/章节组织。每个场景必须回答：谁想要什么、遇到什么阻力、结果如何改变处境。
7. **逐章/逐场景写正文**，进入模式 B。

## 模式 B：大纲→章节正文

1. **读入设定**。读取项目的设定集、文风表、已完成章节及 `设定追踪/story-log.md`（若存在）。无项目结构时，先从用户提供的材料中提炼并补建。
2. **写前对表**。开写前核对：本章出场人物的当前状态（位置、知情程度、情绪）、时间线、已埋伏笔。发现与已有内容冲突时，停下告知用户，不要硬写。
3. **正文写作原则**（完整技法见 `references/craft.md`，写作时必读）：
   - **展示而非讲述**：用可感知的细节传递情绪与信息，禁止直接标注情绪（"他很愤怒"→写出他攥碎的杯子）。
   - **场景推进**：每章由若干场景构成，场景之间要有因果或转折，删除纯过渡段落。
   - **对话承担功能**：对话须同时做至少两件事（推进情节、揭示性格、埋伏笔之一），删掉客套与信息转述式对话。
   - **结尾钩子**：章末留一个未闭合的张力，但不刻意吊诡。
4. **写后登记**。每写完一章，向 `设定追踪/story-log.md` 追加本章摘要：时间线变化、人物状态变化、新埋/回收的伏笔、新出现的人名地名。
5. **交付**。正文以 markdown 写入项目 `章节/` 目录，同时向用户展示正文。

## 模式 C：续写/润色已有内容

1. **先诊断后动笔**。通读用户文本，产出简短诊断：视角是否稳定、时态是否漂移、讲述/展示比例、节奏问题、语言风格特征。先给诊断结论，经用户确认修改方向后再改。
2. **续写**。从文本中提炼隐含的文风表（人称、时态、句长、意象偏好），严格匹配原风格；先与用户确认情节走向再展开。
3. **润色**。按 `references/revision.md` 的修订清单执行，逐层修：结构层（场景顺序、删减）→ 段落层（节奏、过渡）→ 句子层（冗词、展示化改写）。保留作者的个人语感，**不要把文字改顺到失去特征**。
4. **改写/扩写**遵循同一清单，扩写优先补充感官细节与人物内心矛盾，而非注水对话。

## 模式 D：设定管理与一致性维护

1. 项目结构存在时，读 `设定/` 与 `设定追踪/story-log.md`，输出一致性报告：人物状态矛盾、时间线冲突、专名不一致（同一人物两个名字）、未回收伏笔清单。
2. 项目结构不存在时，从用户提供的文本中反向提取设定，生成人物档案与设定集（用 assets 模板），并标注每条设定的出处章节。
3. 伏笔登记：`story-log.md` 中用 `📌 埋设` / `✅ 回收` 标记，报告时列出埋设超过全书 2/3 篇幅仍未回收的伏笔。

## 硬性规则

- 正文用简体中文（用户另有要求除外），交付为 markdown 文件。
- 每章开写前必须完成"写前对表"，长篇连载中设定崩坏多源于跳过此步。
- 不写套话开头（天气开场、"他不知道的是"、梦醒结尾）。第一段必须让人物在具体处境中出场。
- 成稿自检：朗读检查句子节奏；删掉 10% 最弱文字后再交付。
- 涉及内容政策边界（未成年人、暴力、敏感议题）时，在合法合规与平台规范内创作，主动降级处理。
