# 测试报告

对齐大赛加分项「搭建完整测试体系及测试报告」。自动化覆盖必做路径与进阶/创新中的纯逻辑；真连模型、真实 MCP 子进程、安装包启动列为手工项，以录屏为佐证。

## 1. 测试环境

| 项 | 值 |
|----|----|
| OS | 开发机 macOS；Windows 可执行同一命令 |
| Python | 3.10+（推荐 3.12；MCP SDK 需 3.10+） |
| Node | 20+ |
| 后端 | FastAPI + pytest + pytest-asyncio + httpx ASGI |
| 前端 | Vitest |
| 一键入口 | `scripts/run_tests.sh` |

数据目录在用例内指向 `server/tests/.testdata/`（或临时目录），不污染评委本机 `~/.personal-super-assistant`。

## 4. 执行命令

```bash
./scripts/run_tests.sh
# 或
cd server && PYTHONPATH=. python -m pytest tests -q
cd apps/desktop && npm test
```

`run_tests.sh` 会优先激活 `server/.venv`；前端无 `node_modules` 时跳过 Vitest 并提示先 `npm install`。

## 5. 结果摘要

本地开发机执行（以提交前最新一次 `pytest -q` / `vitest run` 为准）：

- 后端：`tests/` 目录用例全部收集并执行；自动化范围内目标 **100% 通过**。  
- 前端：3 个测试文件通过。  
- 未纳入默认门禁：真实 LLM、真实飞书/企微、本机 MCP npx 进程、Electron 窗口 E2E、三端安装包冒烟。

提交交付包前请再跑一遍 `./scripts/run_tests.sh`，将终端摘要粘贴到本节约「执行记录」或作为录屏片头。

## 6. 手工验收项

与 `docs/演示录屏清单.md` 对齐，评委或选手至少覆盖：

1. 配置真实 LLM Key，完成一轮流式对话（含思考区若模型支持）。  
2. 打开本地文件夹后 `fs_read`/`fs_write`；写文件走确认闸，确认与拒绝各一次。  
3. `/file-summarize` 斜杠激活；技能页试运行。  
4. 启用一个 MCP（可为 filesystem），Discover 后对话出现工具卡片。  
5. 飞书：填 APP_ID/SECRET 后发一条测试消息（无账号则口头说明预置项）。  
6. 长对话触发压缩标记；项目内第二会话能带上第一会话摘要（可选）。  
7. 资料库上传/挂载后检索命中；对话引用该库。  
8. 审计导出 Markdown；清单勾选并导出。  
9. 自动化：创建一个「几分钟后」的一次性任务，等待跑出运行记录。  
10. 本机架构安装包冷启动（能测几端测几端）。

## 7. 已知限制

- Python 3.9 无法安装官方 MCP SDK；Discover 返回错误文案，其余功能可用。  
- 真实 MCP 依赖本机 Node/`npx` 与网络；自动化不拉起外部进程。  
- 知识 FTS 异常时后端可回退 LIKE。  
- 联网搜索未配 API 时走 DuckDuckGo/Bing，受网络与反爬影响。  
- Electron E2E 未默认进 CI，稳定性评分请结合录屏。
