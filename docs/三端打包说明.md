# 三端打包说明

目标平台（赛题约束）：**Windows x64**、**macOS Intel (x64)**、**macOS ARM (arm64)**。Python 原生扩展不宜交叉编译，**请在对应架构真机或 CI 上分别构建 sidecar**，再在该机打 Electron 包。

总流程：

```text
1. 本机构建 sidecar → resources/sidecars/{os}-{arch}/
2. ./scripts/build-desktop.sh（Windows: scripts\build-desktop.cmd）→ apps/desktop/release/
3. 将 release 与（可选）sidecars 拷入交付 ZIP
```

## 1. 后端 sidecar（PyInstaller）

脚本已封装：macOS/Linux 用 `scripts/build-sidecar.sh`，Windows 用 `scripts/build-sidecar.cmd`（内部调用 `build-sidecar.ps1` 并绕过执行策略）。脚本会：

- 断言 `third_party/hermes-agent/model_tools.py` 存在  
- 确保 `server/.venv`，安装 `requirements.txt` + PyInstaller，并校验 `import uvicorn`  
- `--add-data` 打入 Hermes 与 `skills/`，`--collect-submodules=uvicorn`  
- 输出 onefile 到 `resources/sidecars/{platform-arch}/`

```bash
# macOS / Linux
./scripts/build-sidecar.sh
```

```bat
REM Windows：在项目根目录用 cmd 或 Git Bash 执行（不要直接双击 .ps1）
scripts\build-sidecar.cmd
```

PowerShell 默认禁止运行未签名脚本。若必须直接跑 `.ps1`：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\build-sidecar.ps1
```

手动等价（以 macOS ARM 为例）：

```bash
cd server
source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt pyinstaller
# 详见 scripts/build-sidecar.sh / .ps1 的 pyinstaller 参数（hidden-import uvicorn 等）
./scripts/build-sidecar.sh
```

产物命名：

| 本机 | 目录 | 文件名 |
|------|------|--------|
| macOS arm64 | `resources/sidecars/darwin-arm64/` | `server-darwin-arm64` |
| macOS x64 | `resources/sidecars/darwin-x64/` | `server-darwin-x64` |
| Windows x64 | `resources/sidecars/win32-x64/` | `server-win-x64.exe` |

开发态无 sidecar 时，Electron Main 自动回退：`server/.venv` 中的 Python + `uvicorn app.main:app`。

Windows 若安装包仍报 `No module named 'uvicorn'`：多半是**旧安装包里的旧 sidecar**。请同步最新 `scripts/build-sidecar.ps1` 后执行：

```bat
scripts\build-sidecar.cmd
scripts\build-desktop.cmd
```

构建日志必须出现 `smoke OK`。然后用**新的** Setup 安装（或先卸载旧版）；不要只替换源码目录而不重打安装包。

## 2. 桌面客户端（electron-builder）

配置在 `apps/desktop/package.json` 的 `"build"` 字段：

- mac：`dmg` + `zip`（脚本按本机架构：ARM 只打 arm64，Intel 只打 x64）  
- win：`nsis`，arch `x64`  
- `extraResources`：mac 从 `darwin-${arch}/`、win 从 `win32-${arch}/` 拷到包内 `sidecars/`（不要用 electron-builder 的 `${os}`，mac 上会解析成 `mac-x64` 而不是 `darwin-x64`）

**一键打包**（先打好对应 sidecar，再在**同一台机器**执行）：

```bash
# macOS（Apple Silicon → arm64 dmg；Intel → x64 dmg）
./scripts/build-desktop.sh
```

```bat
REM Windows x64 → NSIS exe
scripts/build-desktop.cmd
```

脚本会：补齐 Homebrew/nvm 等到 PATH；若仍无 `node`/`npm`，macOS 用 Homebrew；Windows **优先从 npmmirror 下 MSI 静默安装**（winget CDN 在国内常报 `0x80072efd`，已降为最后手段）→ 设置国内镜像 → `npm install`（只装项目依赖）→ 编译前端 → electron-builder。缺 sidecar 会直接失败。MSI 也失败时，手动打开 https://npmmirror.com/mirrors/node/v22.14.0/node-v22.14.0-x64.msi 安装后新开终端重试。

产物在 `apps/desktop/release/`：

| 本机 | 安装包 |
|------|--------|
| macOS arm64 | `PersonalSuperAssistant-1.0.0-arm64.dmg` |
| macOS x64 | `PersonalSuperAssistant-1.0.0.dmg`（或带 x64 后缀） |
| Windows x64 | `PersonalSuperAssistant Setup 1.0.0.exe` |

手动等价：

```bash
cd apps/desktop
npm install
# Apple Silicon
npm run electron:build:mac
# Intel Mac
npm run electron:build:mac:x64
# Windows
npm run electron:build:win
```

国内网络请走镜像（`apps/desktop/.npmrc` 已配置 npmmirror）。若仍从 GitHub 拉 Electron zip，先 `Ctrl+C`，确认环境变量后再打：

```bash
export ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/
export ELECTRON_BUILDER_BINARIES_MIRROR=https://npmmirror.com/mirrors/electron-builder-binaries/
```

不要在 ARM 机器上强打 darwin-x64（会再下一份 100MB+ Electron）。抽查未打包目录可用 `npm run electron:build:mac:dir`。

Windows 若报 `Cannot create symbolic link` / `winCodeSign`：打开 **设置 → 隐私和安全性 → 开发者选项 → 开发人员模式**，或删掉 `%LOCALAPPDATA%\electron-builder\Cache\winCodeSign` 后重跑 `scripts\build-desktop.cmd`（脚本会无符号链接重解压缓存）。赛题交付包默认不签名。

## 3. 三端分工建议

| 机器 | 做什么 |
|------|--------|
| Apple Silicon Mac | sidecar `darwin-arm64` + dmg arm64；录屏主力 |
| Intel Mac 或 CI | sidecar `darwin-x64` + dmg x64 |
| Windows 10/11 x64 | sidecar `win32-x64` + NSIS exe |

不要把 A 架构的 sidecar 塞进 B 架构的安装包。`extraResources` 的 `${os}-${arch}` 在构建时解析，缺文件会导致安装后后端无法拉起（侧栏红点）。

## 4. 打包后自检

1. 安装包体积合理（含 sidecar + Hermes，会明显大于纯前端）。  
2. 干净账号/另一用户目录启动，确认自动建库、登录、绿点。  
3. 不依赖本机 `python3` 与 `server/.venv`。  
4. 设置页 Hermes 为 available（vendored 已打入）。  
5. 抽查：对话一轮、打开文件夹、技能列表非空。  
6. 设置 → 联网搜索：Key 已保存，或免 Key 时 Bing 能出结果。  
7. 若要启用 MCP（飞书/GitHub 等）：本机需有 Node/`npx`（部分为 `uvx`），从 Finder 打开也会补 Homebrew/nvm PATH。

## 4.1 打包后仍可用 vs 仍依赖本机

| 配置 | 打包后 |
|------|--------|
| 预置技能 / 专家 / MCP 列表、Hermes、schema.sql | 打进 sidecar，空库首次启动会再种 |
| 模型 API Key、会话、记忆、飞书 MCP 凭证 | 在 `~/.personal-super-assistant/assistant.db`，**不进安装包**；同机同用户会沿用 |
| 联网搜索 Key、思考链开关 | 开发态从 `server/.env` 同步到用户目录；设置页可改 |
| 登录账号 | 默认 `admin` / `admin`（勿把自定义密码只写在 `server/.env` 里） |
| 文件白名单、知识库路径 | 绝对路径，换机器需重新选目录 |
| MCP `npx` / `uvx` / Playwright 浏览器 | **不打包**，评委机要自备 Node（及对应浏览器） |
| 本机 `python3` / `.venv` | 不需要，sidecar 自带 |

不要把含真实 Key 的 `assistant.db` 或 `server/.env` 打进交付 ZIP。

## 5. 与一键安装脚本的关系

`scripts/install.sh` 面向**源码评测环境**（检测依赖、装 venv、起 uvicorn、打开 Electron），满足大赛「必须提供 install.sh」，部署完成后无需再手动启动服务。  
安装包面向**无开发环境的双击运行**，满足「可运行构建产物」。两者都要交：脚本保复现，产物保稳定性评分。
