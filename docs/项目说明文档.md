# 个人超级助理 — 项目说明文档

| 项 | 内容 |
|----|------|
| 作品名称 | 个人超级助理（Personal Super Assistant） |
| 定位 | 桌面端 AI 智能体工作台（C/S：Electron 客户端 + 本机 FastAPI） |
| 技术栈 | Electron · React · TypeScript · Python FastAPI · SQLite |
| 目标场景 | 个人办公智能化：对话驱动、本地文件可控、技能与连接器可扩展 |

---

## 1. 项目背景与目标

本项目面向个人办公场景，构建一款**轻量化、可拓展、高可用**的桌面端 AI 智能体工作台。产品形态采用本机前后端分离的 C/S 架构：客户端基于 Electron + React + TypeScript，负责窗口、交互与进程守护；业务能力集中在本机 FastAPI 服务中，统一完成模型调用、Agent 编排、技能、MCP、记忆、知识检索、审计与调度。

设计上围绕四类能力展开：

1. **基础可用**：一键环境搭建、多 Profile 的 LLM 配置、本地文件白名单、可验证的内置技能。
2. **能力拓展**：技能系统、对话内记忆、MCP 连接器、办公 IM 对接（飞书内置工具 + 企微等预置连接器）、流式对话与工具确认体验。
3. **场景落地**：项目空间、本地资料库、工具审计舱、对话转清单、定时自动化，把「能聊」推进到「能办事、可复盘」。
4. **工程约束**：目录分层清晰；Renderer 不持密钥、不直连模型；IPC 仅白名单通道；文件读写必须经过白名单；不破坏桌面端安全基线（`contextIsolation`、关闭 `nodeIntegration`）。

之所以选择「Electron UI + Python 后端」而不是把业务塞进 Renderer，是为了同时满足：桌面端交付形态、OpenAI 兼容生态对接、以及 MCP stdio 子进程等 Python 侧更自然的能力边界。

---

## 2. 整体架构设计思路

系统分为三层，职责单向，禁止业务逻辑渗入 Renderer：

1. **Presentation（React）**  
   登录、新建任务、项目、插件市场（专家 / 技能 / 连接器）、资料库、自动化、审计舱、清单、设置。状态以 Zustand 管理；对话以 SSE 事件流渲染。

2. **Desktop Bridge（Electron Main + Preload）**  
   `contextIsolation=true`，关闭 `nodeIntegration`。Preload 经 `contextBridge` 只暴露白名单 API。Main 负责拉起 / 守护 FastAPI sidecar（开发态回退 `venv` + uvicorn），将 REST / SSE 代理到 `127.0.0.1:18765`，并注入本机 Bearer Token，避免前端持有明文密钥。

3. **Domain / API（FastAPI）**  
   对外提供 `/api/v1/*`。Agent Runtime 组装专家人设、项目指令、记忆、技能摘要、知识片段与历史，调用 OpenAI 兼容 Chat Completions（stream + tools），执行最多 6 轮 Tool-Loop，将 token / reasoning / tool / confirm / compress 等事件以 SSE 推回。

进程关系：

```text
Renderer --IPC--> Main --spawn/HTTP/SSE--> FastAPI --stdio--> MCP child
                                      |
                                      +--> SQLite（~/.personal-super-assistant）
                                      +--> skills/*/SKILL.md
                                      +--> third_party/hermes-agent（vendored）
```

开源参考只学边界、代码自写：桌面交互与打包参考 Cherry Studio；Agent / 压缩 / 技能模块边界参考 DeerFlow；Skills / Tools registry / MCP 连接池参考 Hermes Agent（源码 vendored 于 `third_party/hermes-agent/`，经 `hermes_bridge` 接入，不把 Hermes CLI/Gateway 打进主路径）。缺失 Hermes 时自动降级为内置 `SkillRegistry` + 官方 MCP SDK。

存储采用单机 SQLite。文件读写一律经白名单 `resolve`，拒绝 `..` 逃逸。服务只监听回环地址。

## 3. 核心功能模块介绍

### 3.1 基础能力

| 能力 | 使用方式 | 实现要点 |
|------|----------|----------|
| 环境搭建 | `scripts/install.sh` / `install.ps1`，侧栏绿点表示后端就绪 | 检测 Python/Node、安装依赖、校验 schema、拉起 uvicorn、健康检查并打开桌面端 |
| LLM 配置 | 设置 → 模型：多 Profile、连通性探测、设默认 | `llm_profiles`；密钥仅存后端；接口脱敏；编辑留空不覆盖；仅 Gateway 调模型 |
| 文件白名单 | 对话「打开本地文件夹」或资料库挂载目录 | 写入 `whitelist_roots`；`fs_list/read/write` 校验路径前缀，越权拒绝 |
| 内置技能 | 插件市场 → 技能：列表 / 启停 / 试运行 | `skills/` 下多个 `SKILL.md` 启动扫描入库；含摘要、待办、文本整理等示例 |

登录默认 `admin / admin`（可用环境变量覆盖）换取本机 Token。健康检查：`GET /api/v1/health`（含 db_ok、Hermes 状态）。

### 3.2 拓展能力

**技能系统**  
YAML frontmatter + Markdown 正文。对话侧渐进注入技能目录元数据，全文经 `describe_skill` 或斜杠 `/skill-id` 加载，控制上下文体积。支持 `allowed-tools`、技能 Bundle、Hermes Hub / skills.sh 导入；设置页可开关 Hermes Toolsets。

**MCP 连接器**  
stdio / http / sse 配置入库。预置飞书、企微、GitHub、文件系统、Playwright 等连接器，默认关闭，填凭证后启用。Discover 回写 schema；工具名 `mcp__{serverKey}__name`。Hermes 可用时走连接池热更新，否则回退官方 SDK。

**专家人设**  
预置产品、研发、写作、法务等人设，可在对话与项目中选用。人设与技能 / 连接器 / 资料库解耦绑定，便于按任务组合能力。

**记忆（对话内）**  
按字符预算注入置顶记忆与 FTS 命中；同一项目内多会话共享 `session_summary` 与压缩摘要。对话结束后异步抽取 preference / fact / session_summary。不设独立「记忆中心」页，避免与对话抢注意力。

**对话体验**  
SSE 流式、停止生成、工具卡片、高风险写操作确认闸、消息级上下文用量、思考过程展示（`reasoning_content`）、composer 可选模型 / 专家 / 技能 / MCP / 资料库、本地附件、内置联网搜索（Syncotech API → DuckDuckGo → Bing，可切 Tavily）。长上下文采用消息数 + token 双阈值压缩，摘要写入 `sessions.summary_text`，截断时保证 tool 成对。

**办公 IM**  
飞书：预置 MCP + 内置 `feishu_send_message` / `feishu_lookup_user` / `feishu_create_task`（需应用权限）。企微等通过预置 MCP 对接，客户端不写死商业 SDK。

### 3.3 场景化能力

| 名称 | 说明 |
|------|------|
| 项目 Workspace | 手动创建项目（指令 + 能力绑定）或打开本地文件夹自动建空间；下挂多会话 |
| 资料库 | 先建知识库，再上传文件 / 文件夹或挂载白名单目录；FTS 检索；对话按库引用 |
| 工具审计舱 | 每次工具调用落库：入参 / 结果 / 耗时 / 风险 / 确认状态；筛选、回放、导出 |
| 对话清单 | 从助手回复解析待办，勾选与编辑，可导出到白名单内 Markdown |
| 自动化 | cron / 间隔 / 相对时间定时任务；模板（资料库摘要、Git 站会等）；运行历史 |
| 插件市场 | 专家 / 技能 / 连接器统一货架，降低能力发现成本 |

## 4. 关键技术难点与解决方案

1. **前后端分离下的流式对话**  
   Renderer 不能直连模型、不能持钥。Main 代理 SSE，按 `event/data` 帧解析后经 IPC 回推；登录 Token 缓存在 Main，请求自动附加 `Authorization`。

2. **高风险写操作确认闸**  
   `fs_write`、部分 MCP 与技能写操作进入确认流：SSE `tool_confirm` → 前端确认条 → `/chat/confirm` 或 `/reject`。pending 同时写入内存与 `chat_runs.pending_json`，确认后继续同批 sibling 工具，避免半截 Tool-Loop。

3. **技能 / MCP / 内置工具统一工具面**  
   Hermes 开启时，Skills / MCP / toolsets 只经 `hermes_bridge`，禁止与 `SkillRegistry` 双写。Hermes 关闭时走降级路径，保证演示可用。本仓库自有的 `fs_*`、`web_search`、`knowledge_search`、`schedule_task`、`feishu_*` 始终本地实现，便于白名单与审计闭环。

4. **知识索引与白名单**  
   索引源路径必须先过白名单，避免「资料库」成为任意读盘通道。PDF / Word 无文本时标记索引状态，而不是静默空结果。

5. **长上下文压缩**  
   双阈值触发；tiktoken 估算（失败回退字符近似）；摘要持久化；截断点左移以保证 `assistant(tool_calls)` 与 `tool` 成对。前端展示上下文用量与「已压缩」标记。

6. **三端分发与打包可用**  
   客户端 electron-builder：Windows x64 NSIS、macOS x64 / arm64 dmg。后端 PyInstaller onefile sidecar 打入 `extraResources`，Main 按 `platform+arch` 选择可执行文件。预置专家 / 技能 / MCP / 模型 Profile 在空库首次启动写入。开发态无 sidecar 时回退 venv Python。详见 `docs/三端打包说明.md`。

7. **国内 Electron 二进制拉取**  
   官方源易超时。安装与打包脚本默认走 `ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/`。

## 5. 创新功能亮点

- **工作台而不是纯 Chat**：项目 / 文件夹空间把会话、资料、专家绑定收拢，贴近真实办公路径。
- **可观测**：审计舱把每一次工具调用变成可回放记录，便于核验 Agent 实际行为。
- **可落地**：清单从对话抽出可勾选事项；自动化把「每天摘要资料库」变成无人值守任务。
- **可拓展**：技能包、MCP 预置货架、Hermes Hub，能力不写死在前端。
- **安全默认**：本机 Token、回环监听、确认闸、路径白名单、密钥脱敏展示与掩码返回。

## 6. 工程规范落地说明

- **目录**：`apps/desktop` 为客户端；`server/app` 按 api / agent / mcp / knowledge / memory 分层；`skills` 为技能源文件；`resources/db` 为 DDL。
- **类型**：前端 TypeScript 严格编译；后端 Pydantic v2 入参模型；IPC payload 在 preload 侧收口。
- **安全**：`contextIsolation`；业务大流量不经 IPC 传文件正文；LLM 密钥不进 Git、不进日志明文；设置页对已保存密钥脱敏展示。
- **注释**：Agent、白名单、技能、MCP、知识、审计、IPC 代理等核心模块附中文 docstring，说明职责、约束与副作用。
- **错误**：HTTP 统一 `{ code, message }`；校验失败 422；工具失败写成 `role=tool` 消息，避免循环中断后上下文残缺。

## 7. LLM 配置与调用规则

**原则：只有 Python 后端调用模型；Electron / React 从不直连 LLM。**

设置页写入 `llm_profiles` 与 `app_settings.llm`。密钥仅存后端 SQLite；列表与编辑接口返回脱敏掩码（如 `sk-***cY`）；编辑时留空表示不修改。Gateway 使用官方 `openai` Python SDK：

```text
chat.completions.create(stream=True, tools=...)
```

凡兼容 OpenAI Chat Completions 的服务均可接入（OpenAI、DeepSeek、通义 / 阿里云百炼兼容模式、公司网关、Ollama、LM Studio 等）。支持多 Profile、连通性探测与默认模型切换。工具循环最多 6 轮；连续相同 `(name, args)` 达 3 次则打断，防止死循环。思考类模型的 `reasoning_content` 与正文分流渲染。

打包场景下，预置模型 Profile（含兼容端点）由 `server/app/llm/presets.py` 在空库首次启动写入，便于干净环境开箱可用。

## 8. IPC 通信适配说明

| Channel | 方向 | 用途 |
|---------|------|------|
| `backend:status` | invoke | 后端健康 |
| `backend:restart` | invoke | 重启 sidecar / uvicorn |
| `auth:setToken` / `auth:clearToken` | invoke | 登录态写入 Main，供代理附加 Bearer |
| `dialog:selectDirectory` | invoke | 系统选目录（白名单 / 资料库 / 清单导出） |
| `dialog:selectFiles` | invoke | 选择本地附件 |
| `api:request` | invoke | REST 代理 |
| `api:stream` + `api:stream:event` | invoke + event | SSE 代理 |

禁止 Renderer `require('fs')` 或直连 Node。文件内容读写权限落在后端 API，不经 IPC 传大文件。

## 10. 完整部署步骤

### 10.1 开发态

macOS / Linux：

```bash
chmod +x scripts/*.sh
./scripts/install.sh
```

Windows：

```powershell
.\scripts\install.ps1
```

脚本会检测 python / node、创建 `server/.venv`、安装依赖、检查 `schema.sql`、后台启动 FastAPI 并请求 `/health`，然后打开 Electron 桌面端（Vite 即时构建）。默认账号 `admin / admin`。关闭窗口或 Ctrl+C 结束界面，后端继续监听 `127.0.0.1:18765`。

仅 Web UI（无 Electron）时：后端若尚未运行则 `uvicorn app.main:app --host 127.0.0.1 --port 18765`，前端 `cd apps/desktop && npm run dev`。

### 10.2 安装包交付态

1. 在目标架构机器执行 `scripts/build-sidecar.sh`（macOS/Linux）或 `scripts/build-sidecar.cmd`（Windows），产物放入 `resources/sidecars/{platform-arch}/`。
2. 再执行 `scripts/build-desktop.sh`（macOS）或 `scripts/build-desktop.cmd`（Windows），得到 dmg / exe。
3. 安装后启动即可，无需本机再装 Python。细节见 `docs/三端打包说明.md`。

### 10.3 常见问题

- Electron 安装失败：设置 `ELECTRON_MIRROR` 后重装 `electron`。
- `No module named uvicorn`：开发态须使用 `install.sh` 创建的 `.venv`；安装包异常时需同步最新 sidecar 脚本后重打。
- Cursor 终端里 Electron 异常：`ELECTRON_RUN_AS_NODE=1` 可能干扰；`electron:dev` 脚本已取消该变量。
- Finder / 开始菜单启动后 MCP 找不到 `npx`：Main 与 sidecar 已补常见 Node / Homebrew PATH。

## 11. 操作使用教程

1. 启动后登录（`admin / admin`），确认侧栏绿点。
2. 设置 → 模型：新增或编辑兼容 OpenAI 的 `base_url` / `model` / `api_key`，点「探测」；已有密钥脱敏展示，留空保存不覆盖。
3. 新建任务：可「打开本地文件夹」（自动加入白名单并建空间），或稍后在「项目」里创建项目并写指令。
4. 插件市场：查看预置专家 / 技能 / 连接器；技能可试运行；连接器填凭证后 Discover，需要时「保存过滤并重载」。
5. 发送消息：可选模型、专家、资料库；输入 `/` 弹出技能斜杠；附件从 composer 添加。观察流式正文、思考区、工具卡片。
6. 若出现写文件确认条，核对路径后确认或拒绝。
7. 资料库：新建库 → 快速添加文件或文件夹 → 对话中勾选该库。
8. 审计舱：按工具名筛选，打开回放，导出 Markdown。
9. 清单：从带待办的助手回复生成，勾选后可导出。
10. 自动化：用模板或对话创建定时任务，在列表查看下次运行时间。
11. 关于页：查看 `/health` 与 Hermes 状态；异常时「重试连接 / 重启后端」。

逐步镜头脚本见 `docs/演示录屏清单.md`。

## 结语

个人超级助理把桌面端交互、本机 Agent 运行时与可插拔能力货架组合在一起：基础路径保证「能配模型、能管文件、能跑技能」；拓展路径覆盖技能、记忆、MCP 与办公协同；场景路径再把对话结果沉淀为项目、资料、审计、清单与定时任务。整体以本机安全默认与清晰分层为底线，便于继续迭代为长期可用的个人办公智能体。
