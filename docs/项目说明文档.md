# 项目说明文档

> 作品名称：个人超级助理（Personal Super Assistant）  
> 所选赛题：大赛赛题一「个人超级助理（C/S 架构）」  
> 技术栈：Electron + React + TypeScript 客户端 / Python FastAPI 本地服务端 / SQLite  
> 本文覆盖大赛「项目说明文档」全部必填章节，字数满足 ≥1000 字要求。

## 1. 赛题需求解读

赛题要求基于 Electron + React + TypeScript 标准工程，交付一款轻量化、可拓展、高可用的**桌面端 AI 智能体工作台**，服务个人办公智能化。评分上，架构成熟度（35 分）与全流程稳定性（25 分）权重最高，同时考核交互易用、代码风格与注释。

我们将约束拆成四层来落地：

1. **基础必做**：环境可运行、LLM 可配置、本地文件白名单、内置技能可验证。  
2. **进阶拓展**：技能系统、记忆、MCP、对话体验；并覆盖赛题点名的多办公 IM（飞书内置工具 + 企微等预置连接器）。  
3. **创新设计**：项目空间、本地资料库、工具审计舱、对话转清单、定时自动化。  
4. **硬性约束**：工程规范、安全规范、LLM 只在后端调用、技能标准、IPC 白名单；禁止篡改脚手架安全基线。

交付形态上，赛题写的是 C/S。我们做成**本机前后端分离**：Electron 只做 UI、窗口、进程守护与 IPC 代理；全部业务（模型、Agent、技能、MCP、记忆、知识、审计、清单、调度）在 `127.0.0.1:18765` 的 FastAPI 中完成。这样既满足「必须是 Electron 桌面端」，又让 Python 生态直接对接 OpenAI 兼容接口与 MCP stdio 子进程。

## 2. 整体架构设计思路

系统分为三层，职责单向、禁止业务逻辑渗入 Renderer：

1. **Presentation（React）**  
   登录、新建任务、项目、插件市场（专家 / 技能 / 连接器）、资料库、自动化、审计舱、清单、设置。状态用 Zustand；对话走 SSE 事件流渲染。
2. **Desktop Bridge（Electron Main + Preload）**  
   `contextIsolation=true`，`nodeIntegration` 关闭。Preload 经 `contextBridge` 只暴露白名单 API。Main 负责拉起/守护 FastAPI sidecar（开发态回退 venv + uvicorn），把 REST/SSE 代理到回环地址，并注入本机 Bearer Token，避免前端持有明文密钥。
3. **Domain / API（FastAPI）**  
   `/api/v1/*`。Agent Runtime 组装专家人设、项目指令、记忆、技能摘要、知识片段与历史，调用 OpenAI 兼容 Chat Completions（stream + tools），执行最多 6 轮 Tool-Loop，把 token / reasoning / tool / confirm / compress 以 SSE 推回。

进程关系：

```text
Renderer --IPC--> Main --spawn/HTTP/SSE--> FastAPI --stdio--> MCP child
                                      |
                                      +--> SQLite（~/.personal-super-assistant）
                                      +--> skills/*/SKILL.md
                                      +--> third_party/hermes-agent（vendored）
```

开源参考只学边界、代码自写：桌面交互与打包参考 Cherry Studio；Agent / 压缩 / 技能模块边界参考 DeerFlow；Skills / Tools registry / MCP 连接池参考 Hermes Agent，源码拷贝在 `third_party/hermes-agent/`，经 `hermes_bridge` 接入，不把 Hermes CLI/Gateway 打进主路径。缺失 Hermes 时自动降级为内置 `SkillRegistry` + 官方 MCP SDK。

存储为单机 SQLite。文件读写一律经白名单 `resolve`，拒绝 `..` 逃逸。服务只监听 `127.0.0.1`。

## 3. 核心功能模块介绍

### 3.1 必做

| 能力 | 用户怎么用 | 实现要点 |
|------|------------|----------|
| 环境搭建 | `scripts/install.sh` / `install.ps1`，侧栏绿点 | 检测 Python/Node、装依赖、校验 schema、拉起 uvicorn 并 curl 健康检查 |
| LLM 配置 | 设置 → 模型：多 Profile、探测、设默认 | `llm_profiles`；密钥后端保存、接口返回掩码；仅 Gateway 调模型 |
| 文件白名单 | 对话「打开本地文件夹」或资料库挂载目录 | 写入 `whitelist_roots`；`fs_list/read/write` 校验路径前缀，越权 403 |
| 内置技能 | 插件市场 → 技能：列表 / 启停 / 试运行 | `skills/` 约 20 个 `SKILL.md`，启动扫描入库；含赛题示例三类：摘要、待办、文本整理 |

登录：默认 `admin / admin` 换取本机 Token（可用环境变量覆盖）。健康检查：`GET /api/v1/health`（含 db_ok、Hermes 状态）。

### 3.2 进阶

**技能系统**  
YAML frontmatter + 正文。对话侧只渐进注入技能目录元数据，全文经 `describe_skill` 或斜杠 `/skill-id` 加载，避免撑爆上下文。支持 `allowed-tools`、技能 Bundle、Hermes Hub / skills.sh 导入。设置页可开关 Hermes Toolsets。

**MCP 连接器**  
stdio / http / sse 配置入 SQLite。预置约 20 个连接器（飞书、企微、GitHub、文件系统、Playwright 等），默认关闭，填凭证后启用。Discover 回写 schema；工具名 `mcp__{serverKey}__name`。Hermes 可用时走连接池热更新；不可用时回退官方 SDK。

**专家**  
约 20 个预置人设（产品、研发、写作、法务等），可绑定默认模型 / 技能 / MCP / 资料库。对话与项目可选用。

**记忆（对话内）**  
按字符预算注入置顶记忆与 FTS 命中；同一项目内多会话共享 `session_summary` 与压缩摘要。对话结束后异步抽取 preference / fact / session_summary（失败回退规则摘要）。不设独立「记忆中心」页，避免与对话抢注意力。

**对话体验**  
SSE 流式、停止、工具卡片、写文件等高风险确认闸、消息级上下文用量、思考过程（`reasoning_content` + 可折叠）、composer 可选模型/专家/技能/MCP/资料库、本地附件、内置 `web_search`（Syncotech API → DuckDuckGo → Bing，可切 Tavily）。长上下文：消息数 + token 双阈值，LLM 摘要写入 `sessions.summary_text`，截断时保证 tool 成对。

**办公 IM**  
飞书：预置 MCP + 内置 `feishu_send_message` / `feishu_lookup_user` / `feishu_create_task`（需应用权限）。企微等通过预置 MCP 对接，不在客户端写死商业 SDK。

## 4. 关键技术难点与解决方案

1. **前后端分离下的流式对话**  
   Renderer 不能直连模型、不能持钥。Main 代理 SSE，按 `event/data` 帧解析后经 IPC 回推；登录 Token 缓存在 Main，请求自动加 `Authorization`。

2. **高风险写操作**  
   `fs_write`、部分 MCP、技能写操作进入确认闸：SSE `tool_confirm` → 前端确认条 → `/chat/confirm` 或 `/reject`。pending 同时写入内存与 `chat_runs.pending_json`，确认后继续同批 sibling 工具，避免半截 Tool-Loop。

3. **技能 / MCP / 内置工具统一工具面**  
   Hermes on：Skills / MCP / toolsets 只经 `hermes_bridge`，禁止与 `SkillRegistry` 双写。Hermes off：降级路径保演示不崩。PSA 自有 `fs_*`、`web_search`、`knowledge_search`、`schedule_task`、`feishu_*` 始终由本仓库实现，便于白名单与审计。

4. **知识索引与白名单**  
   索引源路径必须先过白名单（绑定知识库的可读例外有专门测试覆盖），避免「资料库」变成任意读盘通道。PDF/Word 无文本时标记索引状态，而不是静默空结果。

5. **长上下文**  
   双阈值触发压缩；tiktoken 估算（失败回退字符近似）；摘要持久化；截断点左移以保证 `assistant(tool_calls)` 与 `tool` 成对。前端展示上下文用量与「已压缩」标记。

6. **三端分发**  
   客户端 electron-builder：win x64 NSIS、mac x64/arm64 dmg。后端 PyInstaller onefile sidecar，打入 `extraResources`，Main 按 `platform+arch` 选择可执行文件。开发态无 sidecar 则用 venv Python。

7. **国内 Electron 二进制**  
   官方源易超时。`install.sh` 默认 `ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/`。

## 5. 创新功能亮点

- **工作台而不是纯 Chat**：项目 / 文件夹空间把会话、资料、专家绑定收拢，贴近真实办公。  
- **可观测**：审计舱把每一次工具调用变成可回放记录，评委与用户都能核验「Agent 到底调了什么」。  
- **可落地**：清单从对话抽出可勾选事项；自动化把「每天摘要资料库」变成无人值守任务。  
- **可拓展**：技能包、MCP 预置货架、Hermes Hub，不把能力写死在前端。  
- **安全默认**：本机 Token、回环监听、确认闸、白名单、密钥掩码。

## 6. 工程规范落地说明

- **目录**：`apps/desktop` 客户端，`server/app` 按 api / agent / mcp / knowledge / memory 分层，`skills` 为技能源文件，`resources/db` 为 DDL。  
- **类型**：前端 TypeScript 严格编译；后端 Pydantic v2 入参模型；IPC payload 在 preload 侧收口。  
- **安全**：`contextIsolation`；业务大流量不走 IPC 传文件正文；LLM 密钥不进 Git、不进日志明文。  
- **注释**：Agent、白名单、技能、MCP、知识、审计、IPC 代理等核心模块有中文 docstring，说明职责、约束与副作用，对应赛题「注释准确性」评分项。  
- **错误**：HTTP 统一 `{ code, message }`；校验失败 422；工具失败写成 `role=tool` 消息，避免循环中断后上下文残缺。

## 7. LLM 配置与调用规则

**原则：只有 Python 后端调模型；Electron / React 从不直连 LLM。**

设置页写入 `llm_profiles` 与 `app_settings.llm`。Gateway 使用官方 `openai` Python SDK：

```text
chat.completions.create(stream=True, tools=...)
```

凡兼容 OpenAI Chat Completions 的服务均可（OpenAI、DeepSeek、通义兼容模式、公司网关、Ollama 等）。多套 Profile 可探测连通性并指定默认。工具循环最多 6 轮，连续相同 `(name, args)` 达 3 次则打断，防止死循环。思考类模型的 `reasoning_content` 与正文分流渲染。

## 8. IPC 通信适配说明

| Channel | 方向 | 用途 |
|---------|------|------|
| `backend:status` | invoke | 后端健康 |
| `backend:restart` | invoke | 重启 sidecar / uvicorn |
| `auth:setToken` / `auth:clearToken` | invoke | 登录态写入 Main，供代理附加 Bearer |
| `dialog:selectDirectory` | invoke | 系统选目录（白名单 / 资料库 / 清单导出） |
| `dialog:selectFiles` | invoke | 选择本地附件 |
| `api:request` | invoke | REST 代理 |
| `api:stream` + `api:stream:event` | invoke + event | SSE 代理 |

禁止 Renderer `require('fs')` 或直连 Node。文件内容读写权限在后端 API，不经 IPC 传大文件。

## 10. 完整部署步骤

### 10.1 开发态（评委复现首选）

macOS / Linux：

```bash
chmod +x scripts/*.sh
./scripts/install.sh
cd apps/desktop && npm run electron:dev
```

Windows：

```powershell
.\scripts\install.ps1
cd apps\desktop; npm run electron:dev
```

脚本会：检测 python/node、创建 `server/.venv`、安装依赖、检查 `schema.sql`、后台启动 FastAPI 并请求 `/health`。随后 Electron 开发窗加载 Vite，Main 守护后端。默认账号 `admin / admin`。

仅 Web UI（无 Electron）时：后端 `uvicorn app.main:app --host 127.0.0.1 --port 18765`，前端 `npm run dev`。

### 10.2 交付态（安装包）

1. 在目标架构机器执行 `scripts/build-sidecar.sh`（macOS/Linux）或 `scripts/build-sidecar.cmd`（Windows），产物放入 `resources/sidecars/{platform-arch}/`。  
2. `cd apps/desktop && npm run electron:build`，得到 exe / dmg。  
3. 安装后启动应用即可，无需本机再装 Python。详见 `docs/三端打包说明.md`。

### 10.3 常见问题

- Electron 安装失败：设置 `ELECTRON_MIRROR` 后重装 `electron`。  
- `No module named uvicorn`：必须用 `install.sh` 创建的 `.venv`；开发态 Main 会优先该解释器。  
- Cursor 终端里 Electron 异常：`ELECTRON_RUN_AS_NODE=1` 干扰；`electron:dev` 脚本已 `env -u` 取消。

## 11. 操作使用教程

1. 启动后登录（`admin / admin`），确认侧栏绿点。  
2. 设置 → 模型：新增兼容 OpenAI 的 `base_url` / `model` / `api_key`，点「探测」。  
3. 新建任务：可「打开本地文件夹」（自动加入白名单并建空间），或稍后在「项目」里创建项目并写指令。  
4. 插件市场：查看预置专家 / 技能 / 连接器；技能点试运行；连接器填凭证后 Discover，需要时「保存过滤并重载」。  
5. 发送消息：可选模型、专家、资料库；输入 `/` 弹出技能斜杠；附件从 composer 添加。观察流式正文、思考区、工具卡片。  
6. 若出现写文件确认条，核对路径后确认或拒绝。  
7. 资料库：新建库 → 快速添加文件或文件夹 → 对话中勾选该库。  
8. 审计舱：按工具名筛选，打开回放，导出 Markdown。  
9. 清单：从带待办的助手回复生成，勾选一项，可选导出。  
10. 自动化：用模板或对话「帮我创建一个每天 9 点的任务」，在列表查看下次运行时间。  
11. 关于页：查看 `/health` 与 Hermes 是否 available；异常时点「重试连接 / 重启后端」。

逐步镜头脚本见 `docs/演示录屏清单.md`。
